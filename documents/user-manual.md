Generate a comprehensive user manual from the concept documents. The manual is written for **end users** — people who use the application, not developers.

## Structure

1. **Title Page** — Project name, version, date
2. **Table of Contents**
3. **Introduction** — What the application does, who it's for, key benefits
4. **Getting Started**
   - System requirements / prerequisites
   - Installation / setup instructions
   - First steps / quick start guide
5. **Features** — One chapter per major feature:
   - What it does
   - How to use it (step-by-step)
   - Configuration options
   - Screenshots / UI descriptions where applicable
6. **Configuration Reference** — All settings, environment variables, config files
7. **Troubleshooting** — Common problems and solutions
8. **Glossary** — From `00-overview.md`

## Tone & Style

- Clear, non-technical language
- Task-oriented: "How to do X" rather than "X works by..."
- Use numbered steps for procedures
- Use tables for reference information
- Avoid implementation details — focus on what the user sees and does
